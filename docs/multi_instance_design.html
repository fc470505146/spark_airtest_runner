Spark Airtest Runner 多实例并发设计稿

适用项目：spark_airtest_runner；目标：支持雷电模拟器设备矩阵、并发调度、顺序执行用例和报告汇总。

设计目标

当前 runner 只支持一个雷电实例。下一阶段希望升级成配置驱动的设备矩阵执行器，用于验证 Spark Android APK 在不同分辨率、DPI 和模拟器实例上的 UI 适配表现。

  • 支持配置多个雷电实例。
  • 支持设置 concurrency，控制一次最多并发几个实例。
  • 同一个实例内按顺序执行多个 Airtest 用例，避免用例互相抢屏幕和 ADB。
  • 每个实例生成独立日志和 HTML 报告。
  • 最终生成 summary.json 和可读的总览报告。

核心原则

并发单位是“雷电实例”，不是“Airtest 用例”。同一个模拟器同时只能有一个前台 App，也只有一套 ADB、Poco 和输入流，因此同一实例内必须顺序执行。
原则 说明
实例级并发 多个雷电实例可以并发跑；同一实例内的用例顺序跑。
配置驱动 雷电路径、APK 路径、包名、设备矩阵、用例列表都来自 YAML 配置。
安装一次 每个实例在一轮测试开始时安装一次 APK；同一实例内多个 case 复用同一 APK。
明确启动 安装完成后使用 adb install -r 等待 Success，再用 am start -n 启动明确 Activity。
用例状态隔离 同一实例内 case 顺序执行，但每个 case 执行前默认重启 App，避免上一个 case 的 UI 状态、存档状态或失败现场污染后续 case。
失败分层处理 环境阶段失败时中止该实例；单个 case 失败时记录失败并继续执行该实例上的后续 case。
结果结构化 每个 case 都产出结构化结果对象，总览报告和 summary.json 只依赖结构化结果，不依赖控制台输出。
失败可诊断 失败时记录实例名、case 名、阶段、错误消息和报告路径。

默认建议 concurrency: 1。等串行矩阵稳定后，再提升到 2。雷电多开会消耗 CPU、内存、GPU 和磁盘 IO，稳定性优先。

配置校验

多实例版本不保留旧版 instance 兼容逻辑，配置必须显式提供 instances。这样可以避免新旧配置长期并存造成语义漂移，也让执行入口只有一个事实来源。

配置解析阶段应尽早 fast-fail，避免执行到中途才暴露环境错误。以下条件应直接报错并中止：

  • ldconsole 缺失或文件不存在。
  • apk 缺失或文件不存在。
  • package 缺失。
  • instances 缺失或为空。
  • cases 为空。
  • concurrency 小于 1。
  • 任意 case 路径不存在。

package 作为配置项维护，用于安装后确认目标 App、停止 App 和查询启动入口。启动 activity 不作为配置项维护，runner 在 APK 安装后通过 ADB 查询设备 PackageManager 获得。

执行模型

每个实例由一个 worker 负责。worker 内部顺序执行所有 case；多个 worker 由线程池按 concurrency 控制并发数量。

1. 读取配置解析 instances、cases、concurrency。
2. 创建线程池max_workers = concurrency。
3. 提交实例任务每个实例提交一个 run_instance_suite。
4. 实例内顺序执行安装 APK 后按顺序跑所有 case。
5. 收集结果记录通过、失败、报告路径和错误信息。
6. 输出汇总生成 summary.json 和总览 HTML。

伪代码

def run_matrix(config):
    instances = config["instances"]
    cases = config["cases"]
    concurrency = config.get("concurrency", 1)

    with ThreadPoolExecutor(max_workers=concurrency) as executor:
        futures = [
            executor.submit(run_instance_suite, instance, cases, config)
            for instance in instances
        ]

        results = []
        for future in as_completed(futures):
            results.extend(future.result())

    write_summary(results)
    write_index_html(results)

单实例执行流程

def run_instance_suite(instance, cases, config):
    ensure_instance(instance)
    launch(instance)
    serial = wait_adb_ready(instance)
    adb_install_r(serial, config["apk"])
    activity = resolve_launch_activity(serial, config["package"])

    restart_app_per_case = config.get("restart_app_per_case", True)
    results = []
    for case in cases:
        started_at = now()
        try:
            if restart_app_per_case:
                force_stop_app(serial, config["package"])

            start_activity(serial, config["package"], activity)
            wait_poco_ready(serial)
            result = run_airtest_case(case, serial, instance)
        except Exception as error:
            result = CaseResult(
                instance=instance["name"],
                case=case_name(case),
                status="failed",
                stage=current_stage(),
                error=str(error),
                duration_seconds=elapsed_since(started_at),
            )

        results.append(result)

    quit_instance(instance)
    return results
默认建议 restart_app_per_case: true。普通 UI 验收 case 应互相独立，避免隐式依赖；只有明确要验证连续流程或跨场景状态传递时，才考虑关闭该选项。

App 重启语义

restart_app_per_case 默认表示每个 case 前执行一次轻量重启：

adb shell cmd package resolve-activity --brief <apk package>
adb shell am force-stop <apk package>
adb shell am start -n <apk package>/<launchable activity>
wait_poco_ready()

默认不执行 pm clear，避免清除权限、存档、设置和其他测试前置状态。后续如果确实需要更强隔离，可以另行增加 reset_app_data_per_case，但第一版不纳入默认路径。

失败策略

失败位置 处理方式 原因
实例创建、启动、ADB ready、APK 安装、App 首次启动 中止当前实例任务，记录实例级失败。 这些属于环境阶段失败，后续 case 大概率无法执行。
单个 case 执行失败、断言失败、报告生成失败 记录该 case 失败，并继续执行后续 case。 case 之间默认通过重启 App 做状态隔离，一个 case 不应污染整个矩阵。

实现拆分建议

模块 职责
run.py 入口，解析配置，创建运行目录，调度矩阵执行。
runner/ldplayer.py 封装雷电实例创建、修改、启动、关闭和 ADB 命令。
runner/airtest_cli.py 封装 airtest run 和 airtest report。
runner/matrix.py 新增模块，负责单实例 suite、多实例串行执行、实例级并发调度和结果收集。
runner/report.py 新增模块，负责写 summary.json 和总览 HTML。

迭代计划

  1. 把配置从 instance 升级为 instances，不保留旧配置兼容逻辑。
  2. 新增 concurrency，默认值为 1。
  3. 新增配置校验，关键字段、关键路径和空列表在执行前 fast-fail。
  4. 抽出 run_instance_suite，先保持单实例行为不变。
  5. 调整报告目录为实例分层，先消除未来并发下的路径冲突。
  6. 让 AirtestCli.run_case 返回结构化 case 结果。
  7. 串行跑多个实例，验证矩阵语义和报告目录。
  8. 生成 summary.json。
  9. 生成总览 index.html。
  10. 最后接入 ThreadPoolExecutor，实现实例级并发。
建议先交付 V1：多实例串行、每 case 重启、实例分层报告和 summary.json。V1 稳定后再打开并发，这样并发只改变外层调度，不改变 case 执行语义。
